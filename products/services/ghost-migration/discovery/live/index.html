Diagnostic for “blockquote containers empty after import” in Ghost

The public report

On the Ghost forum (forum.ghost.org/t/60053, posted 2025-09-08; 0 replies when observed on 2026-11-08), a user running a universal JSON import from the html field wrote: “the importer strips out all text except br tags when the blockquote contains them”.

What this package does

A small Node harness feeds 8 synthetic HTML inputs to @tryghost/kg-html-to-lexical (direct dependency pinned to 1.4.4, the HTML-to-Lexical converter published by Ghost) and records which text, quote nodes and line breaks survive. It addresses questions Q1–Q4 of the diagnostic handoff. Q5, a real Ghost universal import, is not covered: a converter result is not an import result, and we have not verified which converter version, options or preprocessing Ghost’s importer applies.

Run it

Download the files below into one directory, keeping the package/ layout, then in package/ with Node ^22.22.2 or ^24.15.0:

npm install
node harness.cjs --out result.json; echo $?
npm ls --all > tree.txt

Exit codes: 0 all assertions passed; 1 at least one FAIL or ERROR; 2 package or dependency missing; 3 no htmlToLexical export; 4 fixtures unreadable. A Q1 FAIL with a/b missing would match the report; a Q1 PASS means it was not reproduced at this converter version. Full interpretation: package/README.md.

Known limits

  • No package-lock.json: transitive dependencies (jsdom, lexical, @lexical/*, @tryghost/kg-default-nodes, @tryghost/kg-default-transforms) are not locked and resolve at install time. Attach tree.txt to any report.
  • The dependency was not installed in our sandbox: the default run exited 2 with DEPENDENCY_ABSENT (sandbox-default-run.json).
  • The 12/12 self-tests (node tests/run-stub-tests.cjs, results) use stub converters only. They check harness control flow and say nothing about Ghost or the upstream converter.
  • Upstream conversion and real Ghost imports are untested by us.
