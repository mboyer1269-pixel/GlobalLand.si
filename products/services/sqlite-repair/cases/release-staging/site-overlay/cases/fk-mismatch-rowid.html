“foreign key mismatch” when a foreign key references rowid

The question

Stack Overflow question 79846840 by Wpythonic (unanswered when observed on 2026-11-08, licensed CC BY-SA 4.0) declares FOREIGN KEY(cat_id) REFERENCES cats(rowid)) STRICT and reports sqlite3.OperationalError: foreign key mismatch - "vaccinations" referencing "cats", adding: “Earlier today for whatever reason that error didn't happen when I inserted the values”.

Explanation

The official documentation says: “The parent key must be a named column or columns in the parent table, not the rowid.” In the schema reconstructed from the question, cats has no named key column, so the foreign key is misconfigured. SQLite does not check this when the table is created; it reports it when rows are changed while enforcement is on. The documentation also says: “Foreign key constraints are disabled by default (for backwards compatibility), so must be enabled separately for each database connection.” A connection without PRAGMA foreign_keys = ON would accept the insert, which is consistent with the earlier success; we did not observe what enabled foreign keys on the asker's connection.

Correction

Give cats a named key that aliases the rowid (id INTEGER PRIMARY KEY), copy the old rowid values into it, and reference cats(id). The rebuild we executed on synthetic data, with foreign keys off during the rebuild:

CREATE TABLE cats_new (id INTEGER PRIMARY KEY, name TEXT NOT NULL, birthdate TEXT, fur TEXT, weight_kg REAL) STRICT;
INSERT INTO cats_new (id,name,birthdate,fur,weight_kg) SELECT rowid,name,birthdate,fur,weight_kg FROM cats;
DROP TABLE cats;
ALTER TABLE cats_new RENAME TO cats;
CREATE TABLE vaccinations_new (vaccine TEXT, date_administered TEXT, administered_by TEXT, cat_id INTEGER, FOREIGN KEY(cat_id) REFERENCES cats(id)) STRICT;
INSERT INTO vaccinations_new SELECT * FROM vaccinations;
DROP TABLE vaccinations;
ALTER TABLE vaccinations_new RENAME TO vaccinations;
PRAGMA foreign_keys = ON;

This is not a tested migration for a real database: indexes, triggers, views, other references and existing data were not checked. Work on a backup copy first.

What we actually executed

The real SQLite 3.40.1 C API through Python ctypes, on an in-memory database with synthetic data (inputs and actual reports downloadable):

  • As written, foreign keys off: the insert and join succeed, 1 row (input, report).
  • As written, foreign keys on: preparing the insert fails with rc 1 and the message foreign key mismatch - "vaccinations" referencing "cats" (input, report).
  • Rebuilt schema, foreign keys on: the insert succeeds, the join returns 1, 1, Zophie, rabies (id equals the old rowid), and an insert with cat_id 99 is rejected with rc 19 FOREIGN KEY constraint failed (input, report).

Not executed: the asker's Python code, Python's sqlite3 module and iterdump(), the asker's real database or linked schema (the table was reconstructed from output shown in the question), other SQLite versions or build options.
