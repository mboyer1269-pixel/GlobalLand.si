Several statements in one sqlite3_prepare_v2() string: the second never runs

The question

Stack Overflow question 79919860 by LUN (unanswered when observed on 2026-11-08, licensed CC BY-SA 4.0) prepares CREATE TEMPORARY TABLE T1 AS SELECT * FROM TABLE1 ; SELECT * FROM T1, calls sqlite3_step() once, gets 101 and sees pzTail pointing at the SELECT.

Explanation

The official documentation says: “These routines only compile the first statement in zSql, so *pzTail is left pointing to what remains uncompiled.” The compiled statement is the CREATE ... AS SELECT, which returns no rows, so stepping it executes it and returns SQLITE_DONE (101). The SELECT was never prepared. The documentation also says that if the remaining text “contains no SQL (if the input is an empty string or a comment) then *ppStmt is set to NULL”, and that the caller must delete each statement with sqlite3_finalize().

Fix: loop. Prepare from the current position, step to SQLITE_DONE, finalize, continue from pzTail. Prepare each statement only after the previous one ran, because T1 does not exist before the CREATE executes.

const char *p = sql.c_str();
while (p && *p) {
    sqlite3_stmt *st = nullptr; const char *tail = nullptr;
    if (sqlite3_prepare_v2(db, p, -1, &st, &tail) != SQLITE_OK) { /* sqlite3_errmsg(db) */ break; }
    p = tail;
    if (!st) continue;                 // only whitespace or a comment remained
    int rc;
    while ((rc = sqlite3_step(st)) == SQLITE_ROW) {
        // sqlite3_column_*(st, i): rows of the current statement
    }
    sqlite3_finalize(st);
    if (rc != SQLITE_DONE) { /* error */ break; }
}

Alternative when only the last result matters: run the CREATE with sqlite3_exec(), then prepare the SELECT on its own.
