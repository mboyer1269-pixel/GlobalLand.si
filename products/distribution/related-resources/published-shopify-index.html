Color x Size catalogue to Shopify product CSV

Problem

A public Shopify Community question (topic 575067, dated 2025-11-11, community.shopify.com/t/575067) asked how to bulk-add shoes and leather goods with color and size variants, "total 9000+ unique barcode, and each color variant has 5 pictures". A reply said images per color "may need to manually map or script this". This page offers such a script. That request is historical; we have no evidence that anyone needs this today.

What it does

  • Input variants.csv: style_id,title,color,size,sku,barcode,price (+ optional vendor,product_type,tags), one row per barcode. Input images.csv: style_id,color,position,url, one row per public picture URL.
  • Output: one row per variant sharing a URL handle; Title/Vendor/Type/Tags only on the first row; Option1 = Color, Option2 = Size; Barcodes column; all pictures as product images ordered color by color; each variant's Variant image URL = first picture of its color. UTF-8, LF.
  • Refuses to write (exit 2) on duplicate SKU, barcode or color+size, bad price, conflicting titles, duplicate handles or non-http image URLs. --max-rows-per-file splits without cutting a product.
  • Python 3 standard library only; runs offline on your machine. A synthetic 9000-barcode case ran in about 0.3 s.

Download

  • transform.py (the converter)
  • verify.py (independent re-reader used in our tests; a library) and verify_example.py (runnable command that calls it)
  • fixtures/before-variants.csv, fixtures/before-images.csv (synthetic input), fixtures/after-shopify.csv (expected output)

Usage

python3 transform.py --variants fixtures/before-variants.csv --images fixtures/before-images.csv --out shopify.csv --report report.json
# optional: --max-rows-per-file 4000  --barcode-type gtin
python3 verify_example.py fixtures/before-variants.csv fixtures/before-images.csv shopify.csv
# prints each check as JSON; exit 0 = all passed, 1 = a check failed (put verify.py in the same folder)

Running that command on the downloaded fixtures reproduces fixtures/after-shopify.csv byte for byte (checked before release).

Important limits - read before importing

  • A real Shopify import has never been tested. Column names follow the official help page (help.shopify.com/en/manual/products/import-export/using-csv); Option2 name is inferred from the documented pattern. Compare with the sample CSV from your own admin first.
  • Status and Published on online store are not emitted. Per the docs, omitted values default to active/published, so imported products may go live immediately.
  • Importing over existing handles can overwrite existing products. Try a few products in a development or test store first.
  • Native CSV gives each variant ONE variant image. Showing 5 pictures only for the selected color is a theme or app feature, not something this CSV establishes.
  • Images must already be at public URLs. No inventory, weight, SEO, metafield or market columns.

Le script transform.py (Python 3, bibliothèque standard, hors ligne) transforme un catalogue « une ligne par code-barres » (couleur, taille) et une liste de photos en CSV produits Shopify : une ligne par variante, Option1 = Couleur, Option2 = Taille, chaque variante recevant la première photo de sa couleur. Il refuse d'écrire en cas de SKU, code-barres ou couple couleur+taille en double, ou de prix invalide. Vérification : python3 verify_example.py fixtures/before-variants.csv fixtures/before-images.csv shopify.csv (code de sortie 0 = toutes les vérifications réussies).

Limites : aucun import Shopify réel n'a été testé ; la demande d'origine (2025-11-11) est ancienne et aucun besoin actuel n'est vérifié ; les colonnes Status et Published ne sont pas produites, donc les produits peuvent être publiés immédiatement ; importer sur des handles existants peut écraser des produits ; le CSV natif n'associe qu'une image par variante (une galerie par couleur dépend du thème ou d'une application). Testez d'abord dans une boutique de test.
