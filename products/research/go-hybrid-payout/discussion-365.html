Pre-Answer & Scope Clarification for Proposal #304 (W-001)

Thank you for the triage acceptance into MOONSHOT.md (W-001, Slot 1, Family A) and the rigorous architectural stress test. To address the key points raised during review:

Migration Path & Incremental Adoption:
To support the ~50-case corpus without forcing a disruptive language fork, adoption will be incremental. Unannotated legacy functions default to a conservative ambient region (Cap[Default]), allowing existing statement-walk semantics to apply side-by-side with region-checked code. New or performance-critical task boundaries explicitly opt into explicit or branded region capabilities (Cap[R]).

Interaction with Local Loan Rules (A2/A3) & Managed Blocks:
As confirmed by feasibility spike #336, global region capabilities handle cross-task transfers, but fine-grained, intra-task local loan windows (such as map-slot loans p := &m[k] under Rules A2/A3) remain inside hy-check to prevent sub-allocation slicing overhead. Region capabilities replace cross-task sendability and alias tracking rather than deleting intra-task lexical checks.

False-Positive Elimination:
Within a task holding a live region capability Cap[R], arbitrary idiomatic Go aliasing (such as shared references within chunk shapes or multi-path assignments) is permitted, bypassing historical false-positive errors (HYB-E3001 / HYB-E3004) that previously choked statement-walk flow tracking.

Slot 9 · W-009 (#347) — Official Author Pre-Answer (@lienhoatienphung-svg)

Thank you @limitlessprojects for accepting W-009 (#347) into the MOONSHOT.md ledger (Slot 9, Family C). Below is our direct author pre-answer to the three review points raised in triage (building on and tightening the executable model in PR #452):

1. split(k) Fan-Out Semantics Under Loops and select

  1. Root-Owner vs. Sub-Handle Capability Invariant (is_split: true):
    • tx.split(k) consumes the root tx[T] via O5.2 (Origin::Moved) and yields k sub-handles of type tx_sub[T] (modeled in FnState as Binding { shape: TypeShape::ChanTx(elem), is_split_sub: true }).
    • tx_sub[T] permits tx_sub <- move v (including inside select send arms and for loops) because concurrent sends on an open Go channel are race-free once the payload satisfies O5.
    • Calling close(move tx_sub) on a sub-handle is rejected fail-closed with HYB-E3004 (cannot close non-root split sender handle). Only the lexical scope that owns the unsplit root tx[T] (or the structured supervisor epilogue after all k child tasks join) can issue close(move tx).
  2. Loop-Scoped Fan-Out (for i in 0..N):
    • Inside a loop body, tx <- move v on a single root tx[T] does not consume tx (only close(move tx) or transferring move tx into a spawned task consumes tx).
    • When spawning N worker tasks in a loop (for i in 0..N { task worker(move sub_tx) }), the pre-loop sub_txs := tx.split(N) consumes tx before the loop header and binds each iteration to a distinct element sub_txs[i] (checked by the existing loop back-edge pass in freeze.rs). If close(move tx) appears inside a loop without re-binding tx to a fresh chan[T] before the back-edge, check_loop_backedge already rejects it with HYB-E3003 because close(move tx) is an O5 move!
  3. select Arms:
    • In a select statement, if any arm executes close(move tx), branch-join in FnState marks tx as Moved at the post-select join point, so any subsequent tx <- v or second close(move tx) after the select fails closed with HYB-E3003.

2. Wait-For Epoch Assignment for Channels Crossing Function Returns
