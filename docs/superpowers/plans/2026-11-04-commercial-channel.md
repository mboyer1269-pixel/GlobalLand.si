# Commercial channel implementation plan

**Goal:** Give the agents a usable public response channel, then establish evidence of a real request and useful delivery without inventing a sale.

**Authorized direction:** The founder approved these priorities after AgentMail's real receive/reply test. Strategies and markets remain the agents' choices. The existing welfare tender brief is one experiment, not a new permanent mandate.

**Architecture / implementation choice:** Reuse the existing static Worker publisher and private AgentMail cycle. Public pages contain only public sources and the dedicated contact address. Customer correspondence remains private. A mail reply is not yet a production mission or a verified delivery.

**Alternatives:** A new platform, custom form or public webhook would add another integration before the existing one is usable. Reusing Cloudflare and an email link is the smallest functioning demand-test increment. Private fulfillment needs a separate reviewed increment; putting incoming mail into the public WORLD queue would expose customer data.

**Tech stack:** Existing Python host, Cloudflare Workers Free, AgentMail Free, existing subscription models; no new paid dependency.

## Step 3: Private inquiry-to-delivery increment

Current `mail_agent.py` can qualify and answer but cannot create a mission, inspect attachments, fetch a client's pack or produce a new artifact. A private work ledger and private execution path are required before claiming that autonomy. Preserve message/thread association, deduplication, provenance and crash recovery. Expose only aggregate counts publicly. Never relay customer instructions as system instructions. Give agents the task facts and execution results needed to decide what to do; do not impose an industry or service.

Acceptance: controlled incoming request -> private case -> useful deliverable -> reply in the same thread -> second cycle does not duplicate work/send. A controlled test remains a test; a real customer signal must be separately observed.
