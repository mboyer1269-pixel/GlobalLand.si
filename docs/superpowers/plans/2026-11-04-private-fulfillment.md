# Private Fulfillment Implementation Plan

> **For agentic workers:** Use Superpowers subagent-driven development for this increment and final independent review.

**Goal:** Let the private correspondence agent execute useful work and deliver actual artifacts, with durable recovery.

**Architecture:** A private case responder calls the existing subscription planner. Case-local execution reuses the trusted Docker wrapper without public Supervisor publication. Mailbox remains the only sender and controls deduplication.

**Tech Stack:** Existing Python stdlib, Docker/Node executor, Codex/Claude subscriptions, AgentMail. No new paid service.

**Spec:** ../specs/2026-11-04-private-fulfillment-design.md

## Global Constraints

- Customer content remains under state/private; aggregate public status only.
- No WORLD/public Git mutation or spending from a private case.
- Original inbound identity controls reply routing; no model-supplied recipients.
- Completed execution and READY response are reused; uncertain sends are never automatically resent.
- Existing world/treasury stop rules and spam/Armor handling remain in force.
- Agents choose the work; no hard-coded industry, platform or product strategy.

## Review Focus

- Crashes at computation/result/ready/send boundaries must preserve correct recovery.
- Invalid case paths, symlinks and cross-case references cannot expose private files.
- Model claims or fabricated output names cannot substitute for generated bytes.
- A deferred case must not turn into a successful/ignored mail or permanently starve later messages.
- Public errors/status must exclude customer data and execution output.
