# Event-driven initiative

The founder authorized implementation of autonomous AI employees. Agents choose markets, methods and investments under VISION.md; no new niche choice or per-action approval is needed. This increment makes existing work resume on useful host-observed changes, using the installed Supervisor, controller, broker, mailbox and journals. It does not create another orchestrator, financial authority, public webhook or independent model workers. Code readiness, installation and commercial outcomes remain separate claims.

Baseline: `194ffb36ae7f40ba7a43fadb9dbc3f62e6cc854c`, branch `codex/event-initiative`. The design and independent preflight were resolved into this self-contained spec. Root owns Git and deployment. This work changes code and tests locally; it performs no production, payment, new prospect, account or identity operations.

## Constraints

- Python 3.12+, standard library only; preserve Node 22 executor contracts.
- All productive admissions use `state/supervisor.lock` and installed control; never invoke another supervisor CLI while holding that lock.
- Events grant scheduling eligibility only; all existing agent, tool, financial, private-routing and independent-review authority remains unchanged.
- Preserve task no-replay, mail UNKNOWN, immutable READY, broker budgets, private case budgets and mailbox fairness.
- HALTED in either world or treasury defers production; EXTINCT in either permanently suppresses it. Preserve evidence and existing accounting/publication recovery.
- A discovery cursor, aggregate count or baseline is never proof that a model saw a source.
- Root alone stages, commits and installs; implementation workers leave a reviewable diff.

## Host event ledger and eligibility

Add `scripts/initiative.py`, a host-only durable admission module, with SQLite at `state/private/initiative.sqlite3` (0700 parent, 0600 database and sidecars). No new model tool or incoming-data field can enqueue an event. Validate safe ownership paths, bounded record shapes and exact enums; corrupt initialized state must fail closed with fixed diagnostics, never silently reset dedupe/causality. Do not delete acknowledged identities while their source journals can be rediscovered.

An Event is `{schema:1,id,kind,key,version,target,observed_at,not_before,cause}`. `id = sha256(canonical([kind,key,version]))`; canonical JSON uses sorted keys, UTF-8, compact separators and no NaN. `key` and `version` are SHA256 strings except a validated task/mission key; times are nonnegative integer UTC seconds. `cause = {root_id,parent_turn,depth}` is host-owned. No bodies, addresses, quotes, lease tokens, finance requests or arbitrary paths enter an event. Publication state/mtime is not a source revision.

| Kind / target | Source revision and eligibility |
|---|---|
| `COMMERCIAL_SIGNAL` / `DIRECTOR` | Current-inbox validated observation satisfying `commercial._interpreted`: INBOUND_UNVERIFIED, neither synthetic/automated nor UNKNOWN/NONCOMMERCIAL. Key hashes inbox+message; version hashes normalized observation excluding `observed_at`. It remains an unverified interpretation, never a customer/payment assertion. Acceptance/index repair cannot create another event. |
| `QUEUED_RESULT` / `DIRECTOR` | Terminal queued TOOL result bound to input hash and stable result digest. Include failure and INTERRUPTED; exclude broker-origin, STATUS and administrative records. Capture validated action/type plus lineage privately before executing, because queued journals currently discard request metadata. Never copy financial arguments into this metadata. |
| `PRIVATE_RETRY_DUE` / `PRIVATE_MAIL` | Current-inbox RETRY journal. Version hashes mailbox state, attempts and retry_after; omit case progress so unrelated case writes cannot manufacture another retry revision. Its due time is exactly retry_after. Case PENDING/READY is resumed only through the existing mailbox path, never directly from an event. |
| `LEASE_DUE` / `DIRECTOR` | RUNNING mission, active holder, live lease revision hashed from mission/holder/token/expiry. Due at `max(observed_at, expiry - lease_notice_seconds)`. One notice covers both approaching and passed expiry. Replacement/completion invalidates it; no auto-renewal or reassignment. |

Callbacks follow source commits; periodic local reconciliation repairs missing callbacks. Enumerate stable bounded pages with durable cursors, advancing across deleted cursor keys and cycling so new earlier keys are eventually visited. First activation records historical terminal results/signals as `BASELINED`, not ACKED, and seeds live leases/due private work. A crash during baseline cannot silently classify already-active post-baseline writes as historical: persist the activation boundary/source inventory before enabling producers, then complete its baseline under the shared lock. Callback insertion and reconciliation use identical canonical IDs.

Persist the admission's cause before model/broker execution. Bind broker tasks in `Supervisor.execute_tool` from its trusted origin; bind final queued task IDs/input hashes in the private controller decision before publication. External queued tasks get their own host root only if no prior binding exists. Persist a lease-claim intent (operation/task ID, mission, cause) before WORLD executes; reconcile the exact committed claim using World's durable operation result, including a crash before supervisor result persistence. Add `World.operation_result(operation_id) -> dict | None`, a validated read-only lookup of an existing operation result, to support that repair without reapplying it. Never infer ancestry from mtime, a public description or a model-provided parent. Existing historical sources have baseline lineage, not freshly invented roots.

## Exact coverage, privacy and bounded context

`Controller.prepare_context(*, priority=()) -> dict` returns exactly `{context,assessment,coverage,excluded}`. Build once after worktree/recovery preparation, before inference. `context` is the sole sanitized initial prompt payload. `assessment` is the existing private progress assessment. `coverage` is a private list of `{kind,key,version,representation}`; `excluded` holds fixed reasons for sources that cannot be represented. The receipt stores this manifest and a digest of canonical context. No private keys/hashes enter the prompt. `Controller.context()` remains a compatibility wrapper returning only the context.

Use one commercial read set for `commercial.project(..., scan=scan)`, `commercial.progress_snapshot(..., scan=scan)` and `progress.assess(..., commercial_snapshot=snapshot)`. Add `commercial.scan(root,config,*,priority=()) -> dict` to replace duplicated scans. Prioritize validated admitted source keys before ordinary records within the existing 2,000-record bound. Read each chosen source once and derive both its manifest revision and count contribution from that value. Expose PARTIAL whenever the view is incomplete; an omitted record is not zero demand. Cover a commercial signal only when its exact revision contributes to represented counters. Never publish source IDs, quotes or inferred financial truth.

Retain at most 20 task-result summaries and 2,000 output characters per summary. Reserve slots for oldest eligible pending events before recency filling; selected events beyond available slots stay pending. Summaries include task ID, validated status and explicit `output_truncated` / `output_redacted` flags; coverage describes `STATUS_AND_BOUNDED_OUTPUT` or `STATUS_ONLY`, never full-output comprehension. Use a fixed safe status-only summary when content fails existing screening, and a fixed ineligible disposition when identity/status cannot be validated. Such sources must not repeatedly trigger invisible turns. Pending oldest-first ordering must eventually admit backlog beyond 20 results/2,000 commercial records despite newer arrivals. A mixed batch prioritizes both eligible kinds rather than permanently filling every slot from one class.

Keep treasury's existing aggregate snapshot unchanged. Never expose `state/gateway` records, receipt payloads/signatures, request/args, operation idempotency keys, account cursors or raw finance responses through new context/coverage. For SPEND/RECONCILE tasks, exclude raw result output regardless of whether the existing journal uses `request`, a task dictionary or a queued path; permit only task ID + validated terminal status + fixed redaction marker. Unknown legacy action metadata must not cause a privacy fallback that bypasses screening. No accounting rewrite or new money claim is part of this work.

Broker reads may remain live to observe tool effects within their turn; they must not mutate the frozen initial manifest or ACK additional source revisions. Avoid rebuilding the full initial commercial context merely to serve broker capabilities/recent_results. An older unpublished decision returned by `tick` cannot acknowledge newly claimed sources: recover it first, or return without claiming a fresh batch.

## Private per-revision receipts

Extend `Mailbox.cycle(self,responder,*,on_processed=None) -> dict` and `run_mail_cycle(root,config,*,on_processed=None) -> dict`; existing aggregate returns remain unchanged. `on_processed(receipt:dict) -> None` is host-only and receives `{key,before_version,after_version,after_state,disposition}` for the exact source processed, after its journal is durable. For a fresh message, before_version is null. Allowed dispositions are `CONSUMED`, `REPLACED`, `OBSOLETE`. Do not include customer data or decision text. The callback does not change selection order or mailbox budgets.

An old RETRY is consumed by durable terminal processing, or replaced by a new durable RETRY with its own not_before. Unselected, held, budget-exhausted-without-progress and unsaved attempts produce no consumption receipt. ACK only a matching claimed revision; counts cannot ACK a batch. Callback failure after ACCEPTED must not enter the send-error handler or downgrade it to UNKNOWN; isolate bookkeeping after durable effect handling. Reconciliation can prove an old retry obsolete from a validated terminal/successor record without resending. The old revision/source transition and matching receipt must be recoverable after a crash, even when the callback did not run.

## Admission and restart

Introduce `Supervisor.dispatch(mode,*,now=None) -> dict`, called under the existing lock for legacy modes and new `wake`; use an internal `_cycle`/phase helper for existing work, not subprocess CLI recursion. Local configuration/state/reconciliation/admission precedes cycle Git/finance/model work. Wake acquires the lock nonblockingly; busy/idle returns do zero Git, finance, provider, model or mail network calls. Periodic queue/daily retains existing recovery even without a new model admission; do not make idle wake perform periodic recovery implicitly.

Private `initiative` configuration defaults: `enabled=false`, `debounce_seconds=60`, `director_spacing_seconds=300`, `mail_spacing_seconds=300`, `max_chain_depth=1`, `batch_size=64`, `scan_page_size=200`, `lease_notice_seconds=300`. Strict integers, not booleans; bounds respectively 0–3600, 1–3600, 1–3600, 0–8, 1–200, 1–2000, 0–3600. Invalid configuration never enables scheduling. These are configurable resource controls, not market/spending vetoes. Disabled configuration preserves legacy scheduling apart from the complete stop guard.

One lane per wake; rotate DIRECTOR/PRIVATE_MAIL when both eligible. A director lane is the existing think→queue sequence once under one lock. Periodic think/mail use the same persisted spacing/accounting, so coincident calls cannot double execution. Periodic turns can cover pending and depth-limited events. Queue execution itself must not be skipped because new inference is throttled. External/scheduled roots start at depth 0; an expedited director admission inherits the oldest selected root and `max(selected depths) + 1`, with every parent event/cause retained in its receipt. Its output tasks/leases retain that admission depth. Admit only when the incremented depth is at most max_chain_depth; otherwise leave events periodic-only. Coalescing cannot reset depth or mint a new root. A new periodic strategy turn may have its own root, but consuming an old event must not relabel that event or replay its interrupted admission. Broker/status/outbox/receipt writes never create roots.

An admission receipt stores `{schema,wake_id,trigger,target,turn,cause,event_ids,coverage,context_digest,phase,started_at,finished_at,reason}`; reason is a fixed code. Phases: CLAIMED, STARTED, DECISION_READY, ACKED, INTERRUPTED, OBSOLETE, SUPPRESSED_EXTINCT. Reserve a unique timestamp turn under the lock, greater than prior reserved IDs. CLAIMED can resume its same reservation; STARTED is durably written immediately before the first provider invocation, with frozen context/coverage already persisted privately. `Controller.tick(now=None,*,prepared=None,before_plan=None)` preserves the legacy return `(turn,files)` and invokes before_plan only for an actual new provider turn, after pending-decision checks. Store final decision and task lineage before exposing queued tasks.

Before a director admission becomes STARTED, release selected-but-unrepresented sources back to pending, recording explicit exclusions separately; only exact manifest-covered revisions bind its inference. A DIRECTOR admission STARTED with no durable decision after interruption becomes INTERRUPTED, never a new inference for that admission (even with the old timestamp). Its sources are periodic-only with uncertainty evidence; cooldown cannot silently re-root them. Existing broker/task journals reconcile known effects. PRIVATE_MAIL recovery uses its per-source durable records/receipts rather than looking for a controller decision. Durable director decision resumes publication/ACK only; publication before ACK is also recoverable. ACK only manifest-covered versions and only after durable decision/publication, or exact private processing receipts. Explicit no-action decisions may ACK. Neither ACK nor successful transport means revenue or fulfilled business objective.

Check both stores before productive admissions and effects, including legacy mail/queue callers. Bank EXTINCT is already globally handled in cycle; preserve that and add the missing world guard. HALTED leaves work deferred. EXTINCT records permanent suppression, with no automatic restart. Accounting reconciliation and publication of already-performed facts may continue on existing designated recovery paths, without new model, private computation, send, EXEC or financial commitment.

## Installation and acceptance

With initiative enabled, `start_autonomy.activate` writes an exact managed schedule containing the existing 30-minute think recovery and a one-minute wake probe in `globalland-think`; think now runs its internal queue leg. Preserve existing mail/queue/daily schedules. Recognize only the exact old managed JOB or new managed schedule for upgrade, refuse unknown custom content, back up config/schedule and atomically publish/rollback. Keeping the wake in the same managed file preserves existing `cron_pause.sh` coverage; no additional service or cron filename is needed. No installation occurs as part of implementation.

Acceptance requires fake-clock/model/mail/EXEC tests at all source→insert, claim→start, effect→decision, decision→publish and publish→ACK boundaries; exact privacy/coverage with >20 results and >2,000 commercial records; mailbox fairness/per-revision consumption; no feedback loop, idle network call or lock backlog; legacy and event stop semantics; and scheduler rollback. Run existing focused and full Linux checks. Notification latency includes discovery cadence, due times, admission spacing, lock occupancy and provider availability; a lease notice cannot guarantee completion before expiry. Report code verification separately from deployed operation and verified external profit.
